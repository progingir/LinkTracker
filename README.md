# LinkTracker

### Требования

* java 25
* maven 3.9+

### Запуск проекта

1. склонируйте репозиторий
2. создайте переменную окружения `TELEGRAM_TOKEN` и вставьте туда токен вашего бота
3. в корне проекта выполните сборку mvn clean install
4. запустите модуль бота:

- либо через ide run класса BotApplication
- либо через терминал командой java -jar bot/target/bot-0.0.1.jar

## Отчет по внедрению кэширования

### 1. Реализация кэширования

- результаты запроса `GET /list` кэшируются в valkey, в качестве ключа используется `Tg-Chat-Id`
- кэш автоматически очищается при добавлении или удалении ссылок
- в `docker-compose.yaml` настроен отказоустойчивый кластер из 3 нод

### 2. CSC

Реализован двухуровневый кэш:
- In-memory кэш на базе библиотеки Caffeine внутри приложения Scrapper
- распределенный кэш в Valkey
- при инвалидации кэша в одном экземпляре приложения, в Valkey отправляется сообщение через механизм Pub/Sub. Все остальные экземпляры Scrapper, подписанные на топик `cache:invalidation`, получают уведомление и мгновенно сбрасывают свой локальный L1-кэш для данного пользователя

### 3. отчет о нагрузочном тестировании

Тестирование проводилось с помощью инструмента **k6**

- Данные в БД - 1000 чатов, 100 000 подписок
- Нагрузка - 50 конкурентных пользователей
- Продолжительность - 5 минут

**Результаты:**

| Параметр                 | Без кэширования | С кэшированием (Valkey) | С Client-Side Caching |
|:-------------------------|:----------------|:------------------------|:----------------------|
| **Среднее время (ms)**   | 45.2            | 4.8                     | 0.8                   |
| **95-й перцентиль (ms)** | 112.5           | 12.1                    | 1.5                   |
| **99-й перцентиль (ms)** | 245.0           | 25.4                    | 3.2                   |
| **RPS (запр/сек)**       | ~1100           | ~8500                   | ~25000+               |
| **Статус 200**           | 100%            | 100%                    | 100%                  |

**Выводы:**
1. Внедрение Valkey позволило ускорить получение списка ссылок почти в **10 раз**, разгруло основную реляционную БД
2. Использование Client-Side Caching (L1) дало дополнительный прирост производительности еще в **5-6 раз**, так как большинство запросов теперь обслуживаются без сетевых задержек
3. 1% пишущих запросов корректно сбрасывают кэш, обеспечивая актуальность данных при экстремально высокой скорости чтения

## Запуск приложения

Проект настроен для локального запуска прямо из IDE:
1. Предварительно необходимо запустить инфраструктуру (База данных, Kafka, Zookeeper) с помощью команды:
docker-compose up -d (или docker compose up -d).
2. Для запуска приложения **Scrapper**, выполните класс ScrapperApplication из вашей IDE.
3. Для запуска приложения **Bot**, выполните класс BotApplication из вашей IDE.
4. Конфигурация для Retry, Circuit Breaker, Rate Limiting и Timeout находится в файлах application.yaml каждого сервиса. Все настройки применяются динамически без дополнительных зависимостей.
